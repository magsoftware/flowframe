# ADR-0008: Canonical SVG output and normalization

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-09-30 |
| Owner | Tech lead, Security reviewer |
| Phase | P0.3 |
| Related | PRD §7, §16.1; technical-spec §14; ADR-0021 |

## Context

The PRD pipeline shows "normalize / verify / publish", while other sections describe normalization only for snapshots. It was unclear whether `diagram.svg` and its manifest hash are the raw renderer output or a canonical form. The final verifier also needs a rule for the CSS that D2 emits in its own `<style>` element.

## Alternatives considered

- **Publish raw composed SVG; normalize only in tests.** Snapshot and artifact differ; the manifest hash is less stable across harmless renderer differences.
- **Publish canonical SVG.** Adopted.

## Decision

1. The published `diagram.svg` from `build` and the body SVG from `render` are canonical: normalized, verified and then hashed. The manifest `outputs.svg.sha256` is the hash of those canonical bytes. Snapshot tests compare the published bytes directly.
2. Normalization fixes namespace prefixes, attribute order, lossless numeric serialization and removes only fields listed in this ADR as ignorable. It MUST NOT reorder visible children when painter order matters.
3. Raw renderer SVG is kept only in a diagnostic temporary directory when `--debug` is set.
4. The root element carries the marker comment `<!-- Generated by FlowFrame. Do not edit. -->` as its first child node; normalization keeps it. It identifies FlowFrame artifacts for overwrite protection (ADR-0010).
5. The final verifier accepts renderer CSS only from an allowlist: class selectors, color, fill, stroke, stroke-width, stroke-dasharray, opacity, font-family, font-size, font-weight, font-style properties, and `@font-face` rules whose `src` is a data URI with an allowed font MIME type. Any other at-rule, property, `url()` or import fails verification (policy, exit 5).

## Consequences

- Rebuilding identical inputs within the toolchain equivalence class produces byte-identical `diagram.svg`.
- A D2 upgrade that changes CSS output may require an allowlist update, reviewed with the pin change.

## Open parameters

| Parameter | Phase | Method |

| Exact list of ignorable renderer fields | P0.3 | Inventory nondeterministic fields across repeated renders in separate directories. |

## Verification

- Canonicalization is idempotent: canonicalizing canonical output yields identical bytes.
- Repeat builds in two absolute paths produce identical `diagram.svg` (P6.2).
- Fixtures with forbidden CSS in renderer output are rejected.
